# 重开发范围与迁移路线

本次从旧播放器中提取需求后重新建立可移植基础架构，没有把旧 firmware 改名后继续绑定 ESP-IDF。独立目录是 q2/kernel、q2/platform、q2/app；旧 firmware 保留为现有产品功能和硬件参数的迁移依据。

## 当前状态

| 能力 | 新架构状态 | 后续工作 |
|---|---|---|
| 生命周期/注册/依赖/事件/结果码 | 已实现，宿主测试 | 实机长期运行 |
| Lua runtime/权限/资源回收 | 已实现，API 2 最多 8 VM 协作运行、一个前台与常驻 lifecycle | 异步任务与能力作用域 |
| LittleFS/FatFs | 真实库，私有文本键值，RAM 介质验证 | 真实 Flash/SD 后端和故障注入 |
| SQLite | 真实库，内存数据库，默认关闭 | 持久 VFS、事务与容量评估 |
| TinyUSB | 真实 CDC 栈，测试 DCD 验证 | ESP32-S31 DCD、PHY/IRQ 与实机连接 |
| Display | 文本后端与可选 LVGL；Windows x64 窗口、Lua 标签/按钮/事件 | 实机屏幕驱动、更多资源格式、中文字体、完整 UI API |
| APP 工具 | UUID/SemVer/manifest/模块打包/校验 | 设备安装器、签名、更新回滚 |
| settings/device-info | 可执行独立 Lua 示例 | 完整设置项与默认应用装载 |
| ESP32-S31 | 最小独立接入工程 | 板级设备、产品装配与实机验证 |
| 音频/MP3、按键、电源、无线 | 留在旧 firmware | 按统一组件契约逐项迁移 |
| BT PAN、耳机、Wi-Fi、USB MSC | 新 Kernel 尚未提供 | 迁移后验证手机/耳机兼容性和并发 |

旧 `docs/mini-os-project-plan.md` 中的完整系统愿景继续有效，但其拟议 manifest、协程、OTA、多 APP、UI 等不能直接视作本版已经实现。当前实施契约以 format 2 / API 2 文档为准，不向后冒充旧 API 1。

## 建议实施顺序与验收

1. **板级基础**：注册真实 Flash/SD、按键、显示和电源；两个示例 APP 在设备上可启动，缺失组件可降级，退出无资源遗留。
2. **播放器组件**：迁入音频服务、解码器与缓存；Lua 仅发控制指令和收事件，不承担实时音频处理。验证连续播放、切歌、耳机路由、欠载恢复。
3. **无线和 USB**：独立适配 BT/BLE/Wi-Fi 与 TinyUSB，公开明确的异步协议；能力由目标构建和设备实际状态决定。验证两类手机和耳机组合。
4. **应用管理**：先完成安全解包、可信发布者、校验、事务安装和回滚，再开放下载/OTA；UUID 不随打包改变，数据和安装版本分离。
5. **Mini OS 完整体验**：桌面、系统设置、插件、图形 UI 和后台服务；按 RAM/Flash 实测预算决定并发数，不预设无限扩展。

最小注册协议保持稳定；新增功能应优先扩展组件和可选设备协议。不要为未来功能提前塞入大型 mandatory HAL。
